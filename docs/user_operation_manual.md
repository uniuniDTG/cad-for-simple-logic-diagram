# Logic CAD ユーザ操作マニュアル

**バージョン対応**: 最新の開発版に基づく（DXF を唯一のデータソースとする設計）。

このマニュアルは **Logic CAD アプリケーションの日常的な操作方法** を中心にまとめています。
テンプレート（`symbol_library.dxf`、`frame_template.dxf`）の作成方法や DXF 仕様の詳細は [`user_manual.md`](user_manual.md) を参照してください。

**原則**:
- すべてのデータ（シンボル、配線、注釈、ページ情報、図枠）は **DXF ファイル内に保存**されます。アプリは ezdxf の `Drawing` を唯一の元本として扱います。
- PDF エクスポートは DXF の内容を基に生成するだけです。編集は常に DXF に対して行ってください。
- 変更は Undo/Redo で元に戻せます。頻繁に **保存** することを推奨します。

アプリ内から **表示 → マニュアル…** でこのドキュメント（および `user_manual.md`）を HTML プレビューで閲覧できます。

---

## 1. 起動と初期設定

### 起動方法
```bash
# 仮想環境（uv）有効化後、プロジェクトルートで
python -m logic_cad.app.main
```

- **デバッグモード**: `--debug` 引数または環境変数 `LOGIC_CAD_DEBUG=1` で詳細ログ出力。
- 初回起動時は最小限の標準レイヤ・初回ページ・シンボルライブラリ（`assets/symbol_library.dxf` があればマージ）が自動設定されます。
- 図面の挿入単位は **mm** (`$INSUNITS=4`) に正規化されます。

### 初回操作の推奨
1. **ファイル → 新規** で新規 DXF を作成
2. **プロジェクト設定 → 図面プロパティ…** で図面番号（`$PROJECTNAME`）を設定
3. パレットからシンボルをドラッグして配置
4. **保存**（`.dxf`）

**注意**: `assets/frame_template.dxf` または `generate/frame_template.dxf` が存在すると、新規ページ時に図枠が適用されます。詳細は `user_manual.md` §4 を参照。

## 2. 画面構成

- **メニューバー**: ファイル / 編集 / プロジェクト設定 / テンプレート / 表示
- **左側パレット**: シンボル・特殊ツール（ドラッグ＆ドロップで配置）
- **中央キャンバス**: 図面編集エリア（ズーム・パン・描画）
- **右側プロパティパネル**: 選択オブジェクトの編集（コンテキスト依存）
- **ページバー**: 左端または下部のタブ/一覧（ページ切替・管理）

**ナビゲーション**:
- **ホイール**: カーソル中心にズーム
- **中ボタンドラッグ**: パン
- **Esc**: 配線/注釈ツールのキャンセル
- **Ctrl + クリック**（ページリンクやシンボル本体以外）: リンク先ページへジャンプ

## 3. シンボル配置とパレット

### パレット内容
- **固定ツール**:
  - NOT（ブロック）
  - AND / OR（入力数に応じて動的生成）
  - チェックポイント
  - 配線分岐
  - ページリンク
  - インページリンク
- **ライブラリシンボル**: `symbol_library.dxf` から読み込んだ BLOCK 名（NOT は重複除外）

**操作**:
1. パレットから項目を **ドラッグ＆ドロップ** でキャンバスへ配置
2. ドラッグ中はプレビュー表示（ホットスポット付き）
3. 配置後、**シンボル移動** → 自動で関連配線が再ルーティングされます（AND/OR 入力の最適化も実行）

**シンボル編集**:
- 選択 → 右側プロパティで **SYM**（表示名）を編集・表示/非表示切替
- ATTDEF タグ（`STATIC_LABEL*`, `LABEL*`）も一部編集可能
- 複数選択可（Ctrl または Shift で範囲選択）

**ページ跨ぎ**:
- **ページリンク** / **インページリンク** を配置し、プロパティで対象ページ/UID を指定
- Ctrl+クリックで対象へ移動

## 4. 配線操作（最も重要な機能）

### ツールボタン（左パネル上部）
- **自動配線**（橙枠オン）: ポートを **2回クリック** で自動 Manhattan + OVG ルーティング
  - クリック位置がポート近傍なら `LD_PORT` へスナップして接続判定（手動配線モードでは無効）
- **手動配線**（橙枠オン）: 始点ポート → 中間折れ点（任意回） → 終点ポート
  - 両方同時オンも可能（手動優先）
  - 手動配線はシンボル移動時の自動再配線対象から一部除外可能

**配線プレビュー**:
- カーソル近くに **長さ（mm）** 表示
- 自動時は始点からマウスまでの直線距離、手動時はマンハッタン累積

**特殊**:
- **配線分岐**: パレットから配置してワイヤを分岐
- **チェックポイント**: 配線上の目印
- シンボル移動後、**自動で全関連ワイヤを再配線**（ルーティングエンジン: constrained_router, manhattan, escape, crossings など高度な最適化）
- AND/OR ゲートの入力ポートは **バンドル最適化**（交差最小化、順序考慮）が行われます

**ワイヤプロパティ**:
- 選択後、右パネルで:
  - 論理/値ユニット（`LOGIC` / `VALUE` → 別レイヤ）
  - 矢印表示のオン/オフ
  - ブリッジ（交差部 ARC）は自動生成

**注意**: 配線は `LWPOLYLINE` + XDATA (`type=WIRE`, `unit=...`) で保存。ルーティング失敗時はトースト通知と位置復元が発生します。

## 5. 注釈ツール（ユーザー補助図形）

左パネルのアイコンで **排他的** に有効化（水色枠でアクティブ表示）。配線ツールと同時使用不可。

### 利用可能なツール
| ツール | アイコン | 操作方法 | プロパティで編集可能 |
|--------|----------|----------|---------------------|
| **直線** | 直線 | 2点指定（グリッドスナップ）。**Shift** で水平/垂直拘束 | 線種（CONTINUOUS/DASH/CENTER）、レイヤ |
| **円** | 円 | 中心→半径（グリッド） | 線種 |
| **雲マーク** | 雲 | 左クリックで頂点追加、**ダブルクリック** で確定。始点ダブルクリックで閉じた雲 | 線種、セグメント長（XDATA 保存） |
| **テキスト** | テキスト | クリックでダイアログ入力（スナップなし）。文字高さ既定 4mm | 文字列、高さ、配置 |

- **選択後プロパティ適用**: 右パネルで値変更 → **適用** ボタン
- 雲マークは特殊: `LWPOLYLINE` + bulge + XDATA (`cloud_seg`, `cloud_path_*`) で保存。旧データは自動簡略化
- すべて **LD_ANNOTATION** 系レイヤ + XDATA (`type=USER_...`) で管理
- Delete で削除（Undo 対応）
- OSNAP対象は `LD_PORT` のみ（自動配線モード時のみ）

**ヒント**: 注釈ツール使用中は配線ツールがオフになります。Esc で解除。

## 6. 選択・編集・クリップボード

### 基本操作
- **クリック**: 単一選択（シンボル、ワイヤ、注釈）
- **ドラッグ**: 範囲選択
- **Delete**: 選択削除（ワイヤもまとめて）
- **Ctrl+Z / Ctrl+Y**: Undo / Redo（全操作対応、シリアライズ保存）
- **Ctrl+C / Ctrl+V**: **シンボル + 内部配線** のコピー/貼り付け
  - 両端が選択範囲内のワイヤも複製
  - 貼り付け基準: マウス位置（なければビュー中心）
  - 図枠・目次・ページリンクの一部は除外

### プロパティパネル
コンテキストに応じて表示が変わります：
- **シンボル/ゲート**: SYM テキスト、表示ON/OFF、ラベル編集、位置情報
- **ワイヤ**: 単位、矢印表示、UID
- **注釈**: 線種、テキスト内容、高さ、文字スタイル
- **ページ**: 説明、改訂番号
- **複数選択**: 一括適用可能な項目のみ
- **Align** 機能: 選択オブジェクトの整列（プロパティから呼び出し）

**UID 表示**: 内部で一意の UID が付与され、プロパティやデバッグで参照可能。

## 7. ページ管理

左側の **ページ一覧/タブ**:
- 各行: `[レイアウト名] 説明`（ツールチップに詳細）
- **右クリックメニュー**:
  - ページ追加（名前、改訂、説明）
  - プロパティ
  - **ページを複製…**（内容・配線・注釈を別レイアウト名でコピー。目次用 `0*` は不可）
  - ページ削除
  - 目次の再生成

**目次（TOC）**:
- レイアウト名 `0`, `0A`, `0B`... が目次用
- **CONTENTS_ROW** ブロックをグリッドに自動配置（`LD_CONTENTS_AREA` ガイド使用）
- 再生成で最新のページ情報（`PAGE_DESC`, `PAGE_REV`）を反映
- Ctrl+クリックで対応ページへ移動

**ページプロパティ**:
- 説明 (`page_desc`)
- 改訂 (`page_rev`)
- 図枠の `{{PAGE_*}}` プレースホルダと連動
- ヘッダ変数 `$USERI1` (開始ページ番号), `$USERI2` (総ページ数)

**ページリンク**: プロパティで対象レイアウトを選択。保存時はタブ順（目次先頭 + 自然順ソート）を維持。

## 8. メニュー詳細

### ファイル
- 新規 / 開く / 保存 / 名前を付けて保存
- **PDFにエクスポート…**: 
  - PDF書き出し設定ダイアログ（白黒出力の有無など）
  - 全ページを1つのPDFに（日本語フォントフォールバック、ポートレイヤは除外）
  - 幾何は DXF から ezdxf 描画パイプライン使用

### 編集
- Undo / Redo / 削除 / コピー / 貼り付け
- **雲マークをすべて削除…**（一括クリーンアップ）

### プロジェクト設定
- **図面プロパティ…**: 図面番号 (`$PROJECTNAME` = `{{DWG_NO}}`)
- **レイヤ線設定…**: レイヤの線太・真色（`true_color`）編集ダイアログ

### テンプレート
- **図枠テンプレートを適用…**: 任意 DXF 選択 → 全ページの枠/ブロック/目次ガイド置換 → TOC 再生成
- **シンボルライブラリを再読み込み**: `assets/symbol_library.dxf` を現在のドキュメントにマージ（同名ブロックは内容置換）

### 表示
- **シンボルライブラリ…**: ブロック一覧ダイアログ
- **マニュアル…**: 本マニュアル + `user_manual.md` のブラウザ（`docs/` から自動読み込み）

## 10. PDF エクスポートと他CAD互換

- **PDF**: メニューから設定選択後保存。日本語テキストはシステムフォントにフォールバック。ポート（`LD_PORT_*`）は非表示。
- **他CAD (BricsCAD 等)**: 保存した DXF を開いて共同編集可。`LD_*` レイヤ、XDATA (`LD_APP`, `LD_DOC`), ATTDEF, ブロックを尊重。
  - □文字が出る場合: テキストスタイルのフォントを CJK 対応 TrueType に設定（`user_manual.md` §1 参照）
- **保存時**: 目次シートがある場合 `LD_CONTENTS_AREA` をオフに。標準レイヤ・メタデータ・ドキュメントスタンプを自動適用。

## 11. トラブルシューティング

| 症状 | 原因と対処 |
|------|------------|
| **パレットにシンボルが出ない** | `assets/symbol_library.dxf` がない、または BLOCK 名が `*` 始まり。**テンプレート → シンボルライブラリを再読み込み** |
| **ポートに接続できない** | POINT のレイヤ名が `LD_PORT_IN0_LOGIC` / `LD_PORT_OUT0_LOGIC` 等の正確なパターンでない（番号連番必須）。`user_manual.md` §3-3 参照 |
| **配線がルーティング失敗** | 障害物多すぎ、ポート位置不良。トースト通知後シンボル位置を戻す。手動配線併用や配置調整 |
| **図枠/目次が表示されない** | テンプレート未適用 or `LD_PAPER_FRAME` / `LD_CONTENTS_AREA` 欠如。**図枠テンプレートを適用…** |
| **Undo/Redo が効かない** | 稀なケース。保存後再オープン |
| **雲マークの形状が崩れる** | XDATA 破損。プロパティで再編集 or 削除→再作成 |
| **日本語が□になる (他CAD)** | フォント未対応。テンプレート側で STYLE を修正 |
| **ページ複製ができない** | 目次用レイアウト (`0*`) は対象外 |

**ログ確認**: `--debug` で `[logic_cad:...]` 出力。ルーティング詳細は `LOGIC_CAD_DEBUG_ROUTING_VERBOSE=1` 併用（`developer.md` 参照）。

**エラー時**: トースト通知が出ます。詳細は開発者向け `docs/developer.md` を確認。

## 12. 高度なTipsと注意事項

- **自動再配線**: シンボル移動・削除・ページ操作時にほぼ常に実行。パフォーマンスは `LOGIC_CAD_PERF_ROUTING=1` で計測可（開発者用）。
- **ワイヤの保存**: `LAYER_WIRE_LOGIC` / `LAYER_WIRE_VALUE` / `LAYER_WIRE_BRIDGE`。XDATA でメタデータ保持。
- **複数ページ**: タブ順は自動調整（目次先頭 + 名前自然順）。総ページ数は DXF ヘッダまたはレイアウト数から。
- **カスタムシンボル**: `symbol_library.dxf` に追加（ポートレイヤ必須、ATTDEF `SYM` 推奨）。再読み込みで即反映。
- **テスト用 DXF**: `generate/` 配下のスクリプトで多ページテスト可能（`user_manual.md` §4-4）。
- **開発者向け拡張**: コード変更時は `docs/developer.md` と既存テストを尊重（`tests/` 多数あり）。

**本質的な設計**: アプリは「CAD 互換の論理図エディタ」として、ユーザーが BricsCAD 等と併用しやすいよう **最小干渉・DXF 忠実** を重視しています。不要な自動修正は避け、手動制御を尊重。

## 13. よくある質問（QA） — シンボル（ブロック）編

### Q. シンボル（ブロック）はどこに保存される？
**A.** 配置されたシンボル（`INSERT` エンティティ）は**作業中の `.dxf` ファイル**内に保存されます。

- **ブロック定義**（形状、ポート`POINT`、`ATTDEF`、`SYM` など）もその DXF の `BLOCKS` テーブルに含まれます。
- `logic_cad/assets/symbol_library.dxf` は**テンプレート（ソース）**です。作業用 DXF に**インポート/マージ**されて使用されます。
- **保存時**（File → 保存 / 名前を付けて保存）に、ブロック定義も含めてすべて作業用 DXF に書き出されます。
- BricsCAD などで同じ DXF を開けば、ブロック定義もそのまま見えます（XDATA や LD_* レイヤも維持）。

**原則**: アプリは **ezdxf の Drawing を唯一の元本**とします。外部テンプレートは初期投入用で、以後は作業 DXF が正です。

### Q. 起動時のシンボル（ブロック）は？
**A.** `File → 新規`（`LogicDiagram.new()`）実行時、以下の順で初期化されます：

1. `new_document()` で空の DXF を作成（標準レイヤ・メタデータ付与）
2. 初回ページ（`ensure_minimal_page`）
3. **`import_symbol_library(doc)`** が自動実行
   - `assets/symbol_library.dxf` が存在すればブロック定義をすべてマージ（`*` 始まりのブロックは除外）
   - 存在しなければ **最小スタブのみ**（NOT, CHECKPOINT, WIRE_BRANCH, ページリンク用ブロックなど）を生成
4. パレット（`PalettePanel.refresh_from_document`）には固定項目（NOT, AND, OR, チェックポイント, 配線分岐, ページリンク, インページリンク）＋ライブラリから読み込んだブロックが表示されます。
   - AND/OR は入力数に応じて**動的生成**（`dynamic_gate_factory`）されるため、ライブラリには入れません。

### Q. dxfを開いたときのシンボル（ブロック）
**A.** `File → 開く`（`LogicDiagram.open(path)`）時は以下の挙動になります：

- `readfile(path)` で DXF を読み込み（単位正規化、標準レイヤ確保、目次エリアクリーンアップなど）
- **シンボルライブラリ（`assets/symbol_library.dxf`）は自動でマージされません**
- 開いた DXF ファイル**内に既に保存されているブロック定義**をそのまま使用します

これにより、以前に保存した図面のブロック形状・ポート位置が維持されます。ライブラリを更新して**全図面に反映**したい場合は、**手動で「シンボルライブラリを再読み込み」**を実行してください。

### Q. シンボルライブラリの再読み込みを実行すると？
**A.** メニュー **テンプレート → シンボルライブラリを再読み込み**（`reload_symbol_library(doc)`）を実行すると：

1. `assets/symbol_library.dxf` を読み込む
2. **ライブラリに存在するブロック**について：
   - 既にドキュメント内にあれば **中身を置き換え**（既存エンティティを削除 → 新規エンティティをインポート）
   - 存在しなければ新規追加
3. 配置済みの `INSERT` は**同じブロック名を参照し続ける**ため、**キャンバス上のシンボル形状が即座に更新**されます
4. ライブラリ側に**存在しないブロック**（ユーザが独自に追加したものなど）は変更されません
5. 内部で重複ブロック（`NAME0`, `NAME1`...）が発生しないよう特別処理されています（`Importer` のデフォルト rename 挙動を回避）

**用途**:
- ライブラリを編集した後に即反映したい
- 新しいシンボルを追加した後
- ポート位置や形状を修正した後

**注意**: 再読み込み後、**必ず保存**してください（ブロック定義が作業 DXF に書き込まれます）。

**重要**: ライブラリのブロックを編集する際、**PORT位置（POINTの座標）、ポート数、レイヤ名（`LD_PORT_IN*/OUT*_*`）、シンボル形状**を変更すると、**既存の配線接続がずれたり無効になったり、図形の見た目が変わってしまう**場合があります。変更は最小限に留め、適用後は全関連図面で再読み込みを実行し、**ワイヤの再接続とルーティング確認**を必ず行ってください。

詳細な実装は `logic_cad/core/services/layout_service.py` の `import_symbol_library` / `reload_symbol_library`、および `developer.md` を参照。

## 14. エラーメッセージ（Toast通知）編

アプリは操作結果やエラーを **右下に一時的に表示されるToast通知**（`logic_cad/ui/toast.py`）で伝えます。成功メッセージは短時間、エラーは長めに（5〜8秒）表示されます。主なメッセージと意味・対策をまとめます。

### 主なToastメッセージ一覧

#### エラー・警告系（主に8秒表示）

|| メッセージ | 意味 | 対策 |
||-----------|------|------|
|| **`{UID} 再配線できませんでした。シンボルを元の位置に戻しました。`** | シンボル移動/回転後にワイヤの自動再ルーティング（`reroute_wires_after_symbol_moves` など）が完全に失敗。位置を元に戻して整合性を保っています。 | 配置を少しずらす、周辺のシンボル/ワイヤを整理、障害物（他のシンボルや注釈）を減らす。手動配線ツールを併用。ルーティングが複雑な場合は `--debug` でログを確認（`developer.md` 参照）。 |
|| **`辺の並行移動を適用できませんでした。`** | ワイヤの平行移動（シフト）処理が障害物などで失敗（`scene.py` から呼び出される）。 | 周辺のシンボルや注釈を移動してスペースを確保。手動でワイヤを再描画するか、配置を見直す。 |
|| **`図枠テンプレートの適用に失敗しました: {詳細}`** | `apply_frame_template_from_path` 中にDXF読み込み、ブロック置換、またはページ更新で例外発生。 | 選択したファイルが有効なテンプレートDXF（`LD_PAPER_FRAME`、`CONTENTS_*` ブロックなど）であることを確認。`user_manual.md` §4 を参照。 |
|| **`シンボルライブラリの再読み込みに失敗しました: {詳細}`** | `reload_symbol_library` で `symbol_library.dxf` の読み込み/ブロック置換に失敗。 | ファイルが存在し破損していないか確認。ブロック名が重複していないか、DXFバージョン（R2010推奨）を確認。 |

### Toast通知の特徴
- **スタック表示**: 複数同時発生時は右下に縦に並んで表示（親ウィンドウに追従）。
- **フェードイン/アウト**: 自動でアニメーション。
- **親ウィンドウ依存**: MainWindowを指定すると移動・リサイズ時に位置を調整。
- **プロパティ適用失敗**などは主に `QMessageBox`（モーダルダイアログ）で表示されるためToastとは別。

### 対策の基本方針
1. **Toastが出たら即座にメモ**（特にUIDや詳細メッセージ）
2. **Undo (Ctrl+Z)** で直前の操作を戻す
3. **配置を見直す**: シンボルが密集しすぎていないか、ポートが重なっていないか
4. **デバッグモード** (`--debug` または `LOGIC_CAD_DEBUG=1`) で詳細ログを確認
5. **保存してから** 問題を調査（DXFが唯一の元本）
6. 再現可能なDXFがあれば開発者に提供すると迅速に解決可能

詳細な発生箇所は `ui/main_window/window.py` (`_on_reroute_after_geometry_failed`, `_on_wire_error_message`)、 `ui/scene.py` のワイヤ処理、 `core/services/*` のルーティング系にあります。

#### `scene.py` 経由のその他のワイヤエラーメッセージ（個別）

`DiagramScene` 内でワイヤ接続やルーティング適用時に `_on_wire_error` コールバックが呼ばれるケースです。例外の `str(ex)` を直接Toastで表示するため、メッセージは状況によって異なります。代表例と対策は以下の通りです。

- **`開いた雲マークの点列を生成できませんでした。`**  
  `user_geometry_service` で雲マークのガイドからポリラインを再構築できなかった。  
  **対策**: 雲マークを選択してプロパティからピッチを調整、または削除して新規作成してください。旧データからの移行時によく発生します。

- **ポート接続関連のエラー**（"ポートに接続できません"、"方向が一致しません" など）  
  IN/OUTの組み合わせが不正、またはポートレイヤ名が正しくない。  
  **対策**: シンボルのポートPOINTのレイヤ名（`LD_PORT_IN0_LOGIC`、`LD_PORT_OUT0_VALUE` など）が仕様通りか確認。ライブラリを修正した場合は再読み込み後、再接続。

- **ルーティング失敗の詳細メッセージ**（`route_manhattan_with_escape` や交差スワップ失敗時の例外内容）  
  経路探索が全失敗、バンドル最適化不能、並行移動不可など。  
  **対策**: `--debug` + `LOGIC_CAD_DEBUG_ROUTING_VERBOSE=1` でログを確認しながら、シンボル間隔を広げる、手動配線ツールで中間点を指定、または周辺の注釈/雲マークを整理。

これらのメッセージが出た場合は**表示された全文をメモ**し、該当するシンボル/ワイヤのUIDや位置を確認してください。多くの場合、**PORT位置の変更**や**密集配置**が根本原因です。
